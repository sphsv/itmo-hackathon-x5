# Концепция финального решения «Растём вместе»

Актуальная спецификация: [MODEL_CARD.md](MODEL_CARD.md), [PRODUCT_FINAL.md](PRODUCT_FINAL.md), [DEMO.md](DEMO.md). Предыдущая версия концепта доступна в Git-истории.

## Выбранная механика

Привычные покупки дают проверяемую экономию. Недельная цель выбирается по истории; её выполнение даёт демонстрационную награду и рост семьи. В ростомере отражается семейный результат, не развитие ребёнка.

Пример Ивановых: по восьми предыдущим неделям выбраны фрукты и хлеб, цель 16 ₽. Экономия суммируется по одной или обеим категориям; покупать обе не требуется. Тестовый чек с двумя единицами фруктов подтверждает 16 ₽ и закрывает цель. Повтор не начисляет дважды; полный возврат отменяет результат.

## Границы

- Детские food-миссии («первая ложка», «попробуйте пюре») исключены. Возрастной этап не влияет на товарное назначение.
- Наличие конкретной уценки не известно и не обещается. Слабая история уценки → обычная цель по привычной корзине.
- При недостаточной истории нет выдуманного fallback-товара: цель не назначается.
- Реальная семейная связка и кассовая печать замоканы; приглашения и рефералы не реализованы.
- Лига — только offline CSV; разрыв выражается в баллах без «примерной суммы покупки».
- Нет обученной нейросети или LLM-вызова. Есть интерпретируемая персонализация, машиночитаемое условие и детерминированный движок.
- Product effect не измерен; семейная сумма C и ростомер D проверяются отдельно по PILOT_DESIGN.md.

## Состояния

`deferred` — нет условий для назначения; `assigned` — цель действует; `completed` — активные подходящие чеки достигли порога. Возврат может снова сделать completed → assigned. receipt_id неизменяем; изменение содержимого с тем же ID — ошибка.

Это конечная рабочая механика хакатона. Исходные широкие идеи больше не считаются контрактом реализации.
