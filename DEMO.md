# Финальное демо: цель → чек → повтор → возврат

## Запуск

```bash
python3 run_demo.py
python3 serve_demo.py --db results/defense-01.sqlite3
```

Откройте http://127.0.0.1:8765. Для повторного чистого показа используйте другое имя --db; старые базы не удаляются автоматически. При смене недели или версии политики нужна новая база: старое назначение неизменно.

## Сценарий на 60–90 секунд

1. Выберите Ивановых. Цель: 16 ₽ экономии в категории фрукты или хлеб за W37, по истории до недели назначения.
2. «Почему эта цель?» показывает число чеков, повторяемость категорий, медиану и способ выбора порога. Не обещайте наличие акции.
3. Нажмите «Обработать чек». В специально подготовленном тестовом чеке qty=2, полка=300 ₽, оплачено=292 ₽ за единицу.
4. Получается 16 ₽ к цели; 25 за цель + floor(16/5)=3 базовых балла = **28 баллов**, рост 0,8 за покупочный день +2 за цель = **2,8 см**.
5. «Повторить»: 28 баллов и 2,8 см, без второго начисления. Журнал показывает duplicate.
6. «Отменить чек»: активный результат 0 ₽, 0 баллов, 0 см; цель снова активна.
7. В панели менеджера покажите версии, ограничения оценки и кнопку паузы. Пауза запрещает новые чеки, но разрешает возвраты.

Семья Димы показывает другую цель: 19 ₽ по уценённым фруктам/готовой еде. Для markdown-цели обязателен флаг уценки; обычная покупка в той же категории не закрывает её.

## Дополнительные проверки

- Новый receipt_id и исключённая категория: не даёт игрового прогресса.
- Тот же receipt_id с другим qty: 400, данные не меняются.
- Полный возврат до прихода покупки: последующая покупка не начисляется.
- Отрицательная цена, NaN, qty=0, дробное qty, дата за пределами недели: отклонение.
- Перезапуск сервера с той же базой сохраняет журнал и результат.
- Семейная связка в стенде смоделирована; нельзя показывать её как настоящую интеграцию двух карт.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | /health | Проверка доступности |
| GET | /api/bootstrap | Модельные назначения и метрики |
| GET | /api/state?family=family_ivanovy | Текущее состояние из SQLite |
| POST | /api/receipt | receipt_id, family_id, purchased_on, items |
| POST | /api/cancel | family_id, receipt_id; полный возврат |
| POST | /api/rollout | enabled=true/false; локальная пауза |

POST требует application/json. Сервер слушает 127.0.0.1, проверяет Host/Origin, не предназначен для публичного размещения. Нет авторизации покупателя и trusted signature кассы. Не используйте реальные покупательские данные.

## Резерв

[output/demo](output/demo) содержит скриншоты before/completed/duplicate/returned/mobile и browser_report.json. Это последовательность проверенного демо, не видео. Статическое proto/index.html открывается без сервера, но кнопки намеренно отключены: расчёт не подменяется клиентским макетом.
