## Что получаем на выходе и как это стыкуется

После обоих брифов у команды есть **работающий сквозной сценарий на синтетике**: семья с чеками → агент решает, что ей показать и почему → движок считает рост, лигу и скор → экраны и чек показывают реальные числа из симуляции. Завтра можно показать одну семью насквозь.

| Кто | Что получается | Какой пункт кейса закрывает |
|---|---|---|
| ML-1 | Синтетическая аудитория приложения с реальными долями сегментов X5 и 12 неделями чеков | фундамент для всего; честный ответ на «синтетика манипулятивна»: доли настоящие, поведение модель |
| ML-1 | Агент: тип по чекам → первая механика → объяснение для пользователя и продакта → челлендж недели | персональный челлендж из истории, механизм рекомендации механики, объяснение выбора |
| ML-1 | Мини-eval на 30 профилях с процентом попаданий и худшими примерами | критерий «релевантность ≥70%», с честной пометкой про выборку |
| ML-2 | Движок правил + rules.md на страницу | правила начисления и экономика наград |
| ML-2 | Симуляция 8 недель: ростомеры, лиги, разрыв до топ-3, спасённое | обновление прогресса аватара и места в рейтинге; симуляция на 1–10 тыс. пользователей; проверка H3 |
| ML-2 | Антифрод v0: скор, три кейса, объяснимый порог | «простой скоринг, precision важнее recall, порог объясним» |
| ML-2 | Прототип 4 экранов для двух семей + макет чека | кликабельный прототип 3–4 экрана; вау-элемент для встречи |

**Стыковка:** `data/` от ML-1 → `ai/out/challenges.jsonl` от ML-1 → `sim/` ML-2 читает и то и другое → `sim/out/` даёт числа для `proto/`. До готовности данных ML-2 работает на заглушке из 200 семей той же схемы.

**Чего на выходе не будет, и это нормально для чек-поинта:** доказательства аплифта частоты (в симуляцию сознательно не закладываем), настоящей печати на кассе, интеграций, ответа на каннибализацию уценки. Аплифт и каннибализация живут в экономической модели Ивана как допущения с чувствительностью.

## Задача 1. Движок правил `sim/rules.py` + `rules.md`

Реализовать правила из CONCEPT.md §3 как чистые функции над чеками:
- `savings(receipt)` — экономия за чек;
- `savings_pct(family, week)` — метрика лиги;
- `growth(family, week, challenge_result)` — рост ростомера с капами;
- `points(family, week)` — очки с ×2 за уценку и капом 300;
- `league_assign(profiles)` — лиги 20–50 семей по сегмент × сеть × город-бакет, расширение бакета при <20;
- `gap_to_top3(family, league)` — «до топ-3 — одна покупка на ~N ₽»;
- `referral_status(invite, receipts)` — задержка 72 ч, отмена = не засчитано;
- `fraud_score(family, week)` — пять правил из §3, скор 0–100, текстовое объяснение каждого срабатывания.

Исключённые категории и «детское питание не из уценки» — в одном месте, `sim/exclusions.py`.

`rules.md` — те же правила словами, одна страница, для продуктовых материалов. Все стартовые числа помечены «v0, крутится в симуляции».

**Критерии приёмки:** функции покрыты минимальными тестами на 5 сценариях (обычная неделя, охотник с уценкой, семья без покупок 14 дней, реферал с отменой, чек с алкоголем); скор фрода объясняет словами, почему сработал.

## Задача 2. Симуляция 8 недель `sim/simulate.py`

**Модель поведения (допущения, записать):** семья каждую неделю делает покупки с частотой base_freq; вероятность выполнить челлендж 0,5 для хозяина, 0,3 для остальных; вероятность купить уценку по сигналу 0,6 для охотника, 0,15 для остальных; вероятность миссии этапа 0,4. Аплифт частоты в симуляции **не закладываем** — это то, что мы не можем доказать синтетикой, и жюри это знает.

**Выход:** `sim/out/`:
- `heights.csv` — рост ростомера по неделям на семью;
- `leagues.csv` — позиции и разрыв до топ-3;
- `fraud.csv` — скоры и объяснения, доля семей ≥70;
- три графика PNG: распределение ростомеров на 8-й неделе; **метрика H3** — доля семей, у которых разрыв до топ-3 закрывается одной покупкой (по неделям); доля спасённых продуктов по типам;
- `sim/README.md` с пометкой «синтетика — иллюстрация механики, не доказательство эффекта».

**Критерии приёмки:** запускается одной командой на данных ML-1; метрика H3 посчитана и объяснена; в README перечислены все допущения модели поведения.

## Задача 5. `run_demo.py` (см. DEMO.md)
Одна команда `python run_demo.py --families 2000 --weeks 8 --agent-sample 30 --seed 42` прогоняет всё: данные ML-1 → агент ML-1 → симуляция → числа двух демо-семей в прототип и макет чека.
