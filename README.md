# X5 «Растём вместе» — финальная версия хакатона

Персональная недельная цель по привычным покупкам → подтверждённый чек → понятная экономия → семейный ростомер. Это **рабочий локальный стенд**, не интеграция с реальной программой X5.

В main объединены [PR #1 Егора — данные](https://github.com/sphsv/itmo-hackathon-x5/pull/1) и [PR #2 Ивана — продукт](https://github.com/sphsv/itmo-hackathon-x5/pull/2). Финальная интеграция обновляет модель, событийный движок, оценку и демонстрацию.

## Запустить

Python 3.11+, без внешних библиотек и API-ключей:

```bash
python3 run_demo.py
python3 serve_demo.py
```

Откройте http://127.0.0.1:8765. В интерфейсе: **обработать чек → повторить → отменить**. Прогресс и баллы рассчитываются сервером и сохраняются в SQLite. Простое открытие `proto/index.html` показывает только статический снимок.

Для нового чистого демо сохраните прежнюю базу и задайте другую:

```bash
python3 serve_demo.py --db results/defense-02.sqlite3
```

Альтернатива — `uv sync`, затем те же команды через `uv run python`.

## Реализовано

- Данные: 2 000 синтетических профилей, 41 191 чек, 330 181 строка; отдельная целевая когорта — 510 семей, проверки качества и связности.
- Персонализатор: только история до назначения, безопасные привычные категории, адаптивный порог, объяснение, fallback с уценки на обычную экономию и отказ при недостаточной истории. Это rule-based рекомендательная политика, **не обученная нейросеть**.
- Единые правила для eval, replay и интерфейса: точные копейки × количество, исключения, недельные лимиты, дедупликация, конфликт ID, полный возврат, возврат до покупки.
- Локальный HTTP API, SQLite, мобильный интерфейс, журнал событий и пауза начислений.
- Оценка: временной replay и static baseline; слепой пакет на 40 ситуаций и валидатор человеческих оценок.
- Antifraud: отдельный сценарный benchmark на 40 случаях. Это направление на проверку, не автоматическая блокировка.
- A/B/C/D: фиксированная когорта, единые `variant_id`/`rollout_id`/`rule_version`, событийный replay и сценарная сетка множителей C−B и D−C. `shown`, `accepted`, стоимость награды и latency честно помечены как не измеренные; это **не проведённый эксперимент**.

## Проверенные результаты

| Проверка | Результат |
|---|---:|
| Автоматические тесты, включая HTTP | 28 |
| Целевые семьи / временные эпизоды на систему | 510 / 2 040 |
| Назначено целей в replay | 2 034 / 2 040 |
| Выполнено на следующих синтетических чеках, все эпизоды | 64,6% персонально / 33,7% static |
| Безопасность назначенных категорий и правил | 100% на проверенных эпизодах |
| Историческая поддержка категорий среди назначений | 100% / 71,1% static |
| Antifraud, порог 70, 30 определённых сценариев | precision 83,3%; recall 50,0% |
| Человеческая релевантность / бизнесовый uplift | Не измерены |

Выполнимость — совместимость с неизменённой синтетической корзиной. Пороги двух систем отличаются; это не чистый эффект ранжирования. Replay использовался при разработке, поэтому не является независимым внешним тестом. Старые 96,7% и «43,5% до топ-3» **не используются в финальной оценке**.

```bash
python3 -m unittest discover -s tests -v
python3 scripts/verify_final.py
```

Вторая команда делает два прогона в чистых временных каталогах и сравнивает артефакты между собой и с текущей папкой. Отчёт: [results/verification.json](results/verification.json). Браузерные проверки и снимки: [output/demo](output/demo).

## Границы

Согласие взрослого и семейная привязка заданы в синтетическом стенде. Нет кассовой интеграции, реальных начислений, живого наличия скидок, частичных возвратов, аутентификации и multi-week сервиса. Сервер слушает только localhost. Возрастной этап ребёнка не используется для назначения товарных миссий; детское питание, заменители грудного молока, алкоголь, табак и неизвестные категории не дают игрового прогресса.

Лига — только отдельный offline-просмотр в CSV, без оценки «суммы покупки до топ-3»; рефералы — будущая функция. Старые checkpoint-документы и исходная презентация сохранены как история, не как описание текущего кода. Сырые встречи, секреты и локальная SQLite не публикуются.

При очистке сохранены все файлы из обоих PR. Удалены только прежний checkpoint-PDF, два старых инженерных брифа и промежуточный список заданий из старого main; ссылки на восстанавливаемые версии — [ARCHIVE_INDEX.md](ARCHIVE_INDEX.md). Финальная проверка комплекта — [results/submission_audit.json](results/submission_audit.json).
