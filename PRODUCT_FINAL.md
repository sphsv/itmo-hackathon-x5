# Продуктовые материалы — финальная версия

## Пользователь и ценность

Взрослый пользователь приложения из сегмента «дети до трёх лет». Ситуация — плановое пополнение семейной корзины. Задача — купить нужное, не увеличить лишние расходы и увидеть понятную экономию. Это ситуационная гипотеза, а не вывод из синтетического behavior_type.

Предложение: **«Обычные покупки складываются в понятный семейный результат»**. Недельная цель относится к привычным разрешённым категориям; экономия проверяется по чеку; ростомер показывает результат после покупки. Главная карта лояльности не должна уступать место игре.

## Гипотезы

- Персональная цель помогает заметить выгоду и выбрать X5 для плановой покупки.
- Общий семейный результат добавляет ценность к индивидуальной цели.
- Ростомер добавляет эффект поверх того же семейного результата без игры.
- Добавочный эффект покрывает награды, поддержку, fraud loss и каннибализацию.

Самое рискованное допущение — наличие переносимой корзины вне X5. Ни code replay, ни отзывы о приложениях этого не измеряют.

## Границы готового хакатонного решения

Работают: персонализация, объяснение, fallback/отказ, точный чековый расчёт, повтор и возврат, сохранение состояния, адаптивный интерфейс, техническая оценка и локальная пауза начислений.

Не входят: реальная семейная привязка и приглашения, кассовая печать, денежные начисления, поток наличия уценки, публичный сервис, частичные возвраты. Лига — optional offline CSV, рефералы — будущая функция. Это сокращение объёма, а не обещание скрыто готовой интеграции.

## Основной сценарий

1. Взрослый соглашается участвовать; в стенде согласие явно смоделировано.
2. До плановой закупки видит цель по своей истории и объяснение.
3. Делает нужную покупку; подходящая экономия подтверждается строками чека.
4. Сумма достигает порога → награда и рост семьи.
5. Повтор события не меняет результат; полный возврат пересчитывает цель, награду и рост.

Демо Ивановых: цель 16 ₽ в категориях фрукты/хлеб. Тестовый чек: две единицы фруктов по 292 ₽ вместо 300 ₽ → 16 ₽ к цели, 28 демо-баллов, 2,8 см. Повтор: те же числа. Отмена: 0 баллов и 0 см. Этот чек специально сконструирован для показа, не взят из будущей покупки реального человека.

## Продуктовые решения ↔ код

| Решение | Реализация | Как проверяется |
|---|---|---|
| Не стимулировать лишние покупки | Порог от истории, без минимальной суммы корзины; можно пропустить | MODEL_CARD, review по выполнимости |
| Не придумывать предпочтения | Категории ≥3 исторических недель; fallback/отказ | policy tests; история до назначения |
| Безопасность семейного контекста | Исключения и whitelist; нет детских food-миссий | независимо пересчитанные safety checks и adversarial inputs |
| Объяснять каждое начисление | Единый reducer + чек + audit log | HTTP и browser tests |
| Не наказывать за задержки потока | Дедупликация, отмена до покупки, сохранение SQLite | event tests |
| Разделять цель, семью и игру | A/B/C/D на одной сопоставимой популяции | PILOT_DESIGN; реальный пилот ещё нужен |
| Остановить ошибочную механику | Локальная пауза, отмены продолжают работать | API test kill switch |

## Критерии успеха

До защиты: корректный сквозной цикл и воспроизводимость; безопасность на тестовом наборе; человеческая оценка 40 ситуаций с разбором низких оценок. Технические проверки выполнены; человеческие оценки пока не собраны.

В пилоте: покупочные дни на назначенную семью за 28 дней (ITT), положительная инкрементальная contribution margin после затрат, приемлемые жалобы/неначисления/возвраты. Порог значимого эффекта и guardrails фиксируются до запуска после получения baseline X5. Цель — выбрать простейший вариант с подтверждённым добавочным эффектом, а не максимизировать размер ростомера.

## Риски и проверки

| Риск | Что уже сделано | Что ещё проверить |
|---|---|---|
| Нет переносимой корзины | Выделено как главная гипотеза | Агрегаты X5 / реальный пилот |
| Цель тривиальна или навязчива | Скромный порог, skip без штрафа | Blind review и opt-out в пилоте |
| Нет нужной уценки | Fallback, отсутствие обещаний наличия | Реальный поток ассортимента |
| Каннибализация и награды за обычные покупки | Расходы не названы прибылью; стоимости политик показаны отдельно | Маржа с контрольной группой |
| Двойное/ошибочное начисление | SQLite, dedupe, возвраты, тесты | Trusted receipt API и мониторинг |
| Игры мешают карте на кассе | Ростомер после покупки | UX-тест на реальном приложении |
| Ложный antifraud | Диагностический скор, без блокировки | Независимые реальные метки; сейчас recall 50% на сценариях |

## Вклад AI Product

Иван подготовил продуктовую постановку, вторичный ресерч, экономику, ограничения доказательств, пилот и основу защиты. AI помог сопоставить материалы, оформить гипотезы и связать их с требованиями к модели, событиям и проверкам. При финальной интеграции AI реализовал и проверил код по поручению Софьи. Ручных интервью и независимой человеческой оценки AI не имитировал.

Исследовательские файлы коллеги сохранены в research/. Числа и тематические счётчики RuStore представлены в производном отчёте, сырые выгрузки в репозитории отсутствуют; при финальной инженерной интеграции они не переаудированы. Поэтому в финальной презентации используются качественные выводы, а не заявления о самостоятельно перепроверенном числе отзывов. Переносимые эксперименты не доказывают спрос на ростомер X5.

## Следующий шаг

Отдать reviewer_packet.zip двум независимым оценщикам, разобрать провалы, пройти защиту командой. Затем — согласование данных, размера выборки и экономики реального пилота. Кодом нельзя закрыть отсутствие пользовательского спроса.
